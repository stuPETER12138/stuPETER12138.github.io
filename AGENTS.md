# AGENTS.md

Personal site (stuPETER12138.github.io), forked from the Tufted-Blog-Template. Pages are written in Typst (`.typ`) under `content/`, compiled to static HTML/PDF in `_site/` by `build.py`, and deployed by GitHub Actions on push to `main`. Site copy is Chinese-first; keep new content consistent with existing pages.

## Commands

- `uv run build.py build` — incremental build (HTML + PDF + assets + sitemap.xml + robots.txt + feed.xml)
- `uv run build.py build -f` — full rebuild (cleans `_site/` first); CI runs this, so always verify with it
- `uv run build.py preview` — livereload server on port 8000 (falls back to `python -m http.server`)
- `uv run Tools/watch.py` — watches `content/`, `assets/`, `config.typ` and auto-runs incremental builds; `uv run Tools/watch.py --serve` also starts preview. Preferred dev loop over manual build+preview in two terminals.
- `uv run Tools/gen_blog_index.py` — regenerates the post list in `content/Blog/index.typ` (see Content model); `-n` dry-run
- `uv run build.py clean` / `html` / `pdf` / `assets`
- Requirements: `typst` CLI in PATH (>= 0.15 for MathML math in HTML; older versions warn), `uv`. `build.py` and the `Tools/*.py` scripts are stdlib-only — no pip install needed, run them from the repo root.
- Convert images: `uv run img2webp.py` from `Tools/` (Pillow, deps in `Tools/pyproject.toml`). All three tools documented in `Tools/README.md`.

## Content model

- Each page is `content/<path>/index.typ`; it imports the template via `#import "../index.typ": template, tufted` then `#show: template.with(title: ..., description: ...)`. `content/index.typ` imports from `../config.typ`.
- Blog posts live at `content/Blog/YYYY-MM-DD-slug/index.typ` and must set `title` (required by the index generator) and `description` + `date` in `template.with(...)` (needed by RSS; date also parsed from the folder name). The `#tufted.blog-entry(...)` list in `content/Blog/index.typ` is auto-generated by `Tools/gen_blog_index.py` — after adding/removing a post folder, run it instead of hand-editing the list (everything after the `= 博客` heading is rewritten).
- A `.typ` file with "PDF" in its stem compiles to PDF instead of HTML (e.g. `CV-PDF.typ`).
- Files under `content/` in paths whose first segment starts with `_` are excluded from compilation but tracked as shared dependencies (template mechanism, e.g. `content/_xxx/`).
- Images: commit only `.webp`. JPG/PNG under `content/**/imgs/` are gitignored; convert new images with `img2webp.py` before committing.

## Build pipeline gotchas

- `config.typ` (site-wide) plus `content/_*` files are shared deps: editing them rebuilds all pages.
- `website-url` in `config.typ` feeds the canonical URL, from which `sitemap.xml`, `robots.txt`, and `feed.xml` are regenerated after every build — keep it set to the live domain or generated SEO files will be wrong.
- `feed-dir` in `config.typ` selects which content dirs are included in RSS; post dirs without a resolvable date are skipped with a warning.
- `_site/` is gitignored — never commit it.

## Git / deploy

- Never touch `tufted-lib/` unless intentionally changing the theme.
- `deploy.yml` publishes to GitHub Pages (needs Pages "Source: GitHub Actions"); `cloudflare-pages.yml` deploys to CF project `jiong` (secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`). Both trigger on push to `main`.
- `update.yml` (manual trigger) syncs upstream `Yousa-Mirage/Tufted-Blog-Template` changes into a PR; `.github/.templatesyncignore` protects `content/`, `config.typ`, `assets/custom.css`, READMEs, etc. Don't touch ignore-protected files unless intentional.
- Root `Docs/` is leftover template documentation, gitignored — leave it alone.
- `uv.lock` is ignored repo-wide (even under `Tools/`), so don't expect it in git. `UV_CACHE_DIR/` at repo root is a local uv cache (self-ignored); never touch or commit it.
